# Decision D03: Day-1 Admin Auth, Role Hierarchy, JWT/JWKS Rotation & Refresh Sessions

- **Date**: 2026-11-15
- **Spec**: [SPEC-001](../specs/SPEC-001-infra-scaffold.md)
- **Status**: APPROVED

## 1. Context & Problem Statement
Phase 1 has no customer accounts (`backend-client` is public), while `backend-admin` enforces Day-1 auth backed by shared D1 tables (`users`, `sessions`, `jwks_keys`) with role hierarchy `owner > admin > user`, WebCrypto PBKDF2-100k + pepper password hashing (Free-tier compatible), envelope-encrypted `ES256` JWKS rotation, and `make create-user` CLI provisioning. `backend-client` must be prepared to verify standard JWKS tokens in future phases without schema rework.

## 2. Decision
1. **Shared D1 Auth Schema (Owned by `backend-admin` migrations)**:
   - `users` (`owner > admin > user`; `user` defined in schema for future customer accounts, inactive in Phase 1).
   - `sessions` (SHA-256 hashed refresh tokens, `family_id`, rotation & replay revocation).
   - `jwks_keys` (`kid`-indexed public keys + AES-256-GCM encrypted private keys for `backend-admin` signing).
2. **`backend-client` Phase 1 Posture**:
   - No customer login/signup routes in `SPEC-001` (public endpoints only).
   - Scaffold includes a reusable JWKS-compatible JWT verification module (`ES256`/`RS256`) reserved for future authenticated customer/Cloudflare Access routes.

## 3. Rationale
- **Security (#1)**: Keeps auth issuance, user credentials, `PASSWORD_PEPPER`, and `KEY_ENCRYPTION_KEY` completely isolated from `backend-client` while preparing `backend-client` for stateless JWKS verification later.
- **Technical Debt (#2)**: Shared role/JWT model prevents breaking schema migrations when customer accounts are added later.
- **Speed (#3)**: Avoids implementing unused customer login flows during Phase 1 and stays within Workers Free tier limits.

## 4. Consequences
- `backend-client` MUST NOT bind `KEY_ENCRYPTION_KEY` or `PASSWORD_PEPPER` and MUST NOT expose customer signup/login routes in `SPEC-001`.
- All `backend-client` routes in `SPEC-001` operate under `D04` public-endpoint defenses.
