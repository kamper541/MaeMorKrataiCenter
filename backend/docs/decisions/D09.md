# Decision D09: Master-Data Integrity Rules

- **Date**: 2026-11-21
- **Spec**: [SPEC-002](../specs/SPEC-002-master-data-to-backend.md)
- **Status**: APPROVED

## 1. Context & Problem Statement
The Spectre audit of SPEC-002 found that create/update references, key renames, the shape of love-status maps, concurrent check-then-act races and several daily-data details were undefined. The developer accepted all eight recommendations.

## 2. Decision
1. A create or update that names a card, category or love-status key that does not exist returns `400` with code `INVALID_REFERENCE`.
2. Keys are immutable. A PUT whose body key differs from the path returns `400`; renaming is create new, move dependents, delete old. A situation may move to another existing non-`love` category.
3. `meanings`, `details` and `love_by_status` always return every current love-status key, `null` where no text is stored (for example after a new love status is created). `missing_fields` is computed by the server from `null` daily texts.
4. References are enforced by the database inside the write. Love-status texts are stored as child rows with foreign keys, no cascade, so concurrent requests cannot leave orphans.
5. An art entry's `art` must equal its card's `art`; a card with `art: null` cannot have an art entry.
6. The public daily endpoint serves entries regardless of `approved_for_web`.
7. Creating, updating or deleting a love status also bumps the daily `updated` and `version`, because the daily document lists love statuses.
8. A daily `version` with no trailing date gets `-YYYY-MM-DD` appended.

## 3. Rationale
- **Security (#1)**: Database-enforced references and immutable keys remove race-condition and orphan bugs; no inconsistent public data.
- **Technical Debt (#2)**: Child rows with foreign keys make love-status maps queryable and safe to extend without rewriting 78 JSON blobs. A computed `missing_fields` cannot drift.
- **Speed (#3)**: Clear error codes and rules make every admin endpoint testable.

> Amended by [D10](D10.md): deleting a category no longer returns `409`; its items become uncategorized.

## 4. Consequences
- The D1 schema stores per-love-status texts (card meanings, card details, daily love texts) as rows keyed by (card, love status), not as JSON maps.
- Deleting a love status requires deleting its stored texts first (`409` otherwise).
- Public responses may contain `null` in love-status maps; the contract allows it.
