# Decision D06: Admin Master-Data Writes Are Last-Write-Wins

- **Date**: 2026-11-21
- **Spec**: [SPEC-002](../specs/SPEC-002-master-data-to-backend.md)
- **Status**: APPROVED

## 1. Context & Problem Statement
Admins (owner and reader, both role `admin`) can create, update and delete master data. Two admins could edit the same record at the same time. Options: last write wins, or optimistic concurrency (row `version`, stale write rejected with `409`).

## 2. Decision
Last write wins. No row version and no `409` on concurrent edits. Every write is still recorded in `audit_events`, so overwritten changes can be traced.

## 3. Rationale
- **Security (#1)**: No impact; auth and audit are unchanged.
- **Technical Debt (#2)**: No version column or conflict handling to maintain. About 3 admin accounts make collisions an edge case.
- **Speed (#3)**: Simpler endpoints and tests.

## 4. Consequences
- A concurrent edit can silently overwrite another admin's change. The audit trail shows both writes.
- If collisions become a real problem, add optimistic concurrency as a new proto-spec.
