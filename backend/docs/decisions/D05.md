# Decision D05: 10-Minute Public Cache TTL for Master-Data GETs (No Invalidation Yet)

- **Date**: 2026-11-21
- **Spec**: [SPEC-002](../specs/SPEC-002-master-data-to-backend.md)
- **Status**: APPROVED

> Numbering note: D01–D04 live in `docs/admin/decisions/` and `docs/client/decisions/` (pre-merge). From D05 on, decisions live once in `docs/decisions/` and apply to both services.

## 1. Context & Problem Statement
Master data (cards, daily content, art sizes, taxonomy) changes rarely. The developer wants identical requests served from a cache, and edits to show up promptly. D04 sets `Cache-Control: no-store` on dynamic responses.

Research ([2026-11-20-workers-cache-invalidation](../researches/2026-11-20-workers-cache-invalidation.md)) found that both Workers run on `*.workers.dev`, where `caches.default` is a no-op. Cross-Worker invalidation needs either a D1 version counter + ETag (Option A) or Workers Cache with service-binding purge (Option B, unproven in workers-rs).

## 2. Decision
- Successful (`200`) responses from the public master-data GET endpoints on `client` return `Cache-Control: public, max-age=600`.
- No invalidation on admin edit in this spec. Edits may take up to 10 minutes to reach a browser that already cached the response.
- All error responses (4xx, 429, 5xx) and every `admin` response stay `Cache-Control: no-store` (D04 unchanged for them).
- Invalidation (Option A or B) is deferred to `TODO-011`.

## 3. Rationale
- **Security (#1)**: Only public, non-personal data is cached. No new secrets, tokens or bindings. Admin responses are never cached.
- **Technical Debt (#2)**: One header; no cache-key or version machinery to maintain until it is needed.
- **Speed (#3)**: Smallest change that meets "rarely changing data should be cached".

## 4. Consequences
- On `*.workers.dev` the TTL is effective in browsers only; every new visitor still reaches the Worker and D1 once. Edge caching starts working without code changes once a custom domain is attached.
- The 10-minute staleness is documented in `docs/api/client/openapi.yaml` so frontend knows.
- The existing CORS middleware already sends `Vary: Origin`, so cached responses stay correct per origin.
